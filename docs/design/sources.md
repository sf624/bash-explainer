# Facts and their sources

Status: agreed by the maintainer on 2026-10-31. Stage SA (the guards) is in progress; stage SB goes into the UX steps; stage SC waits until after 0.10.0. The order is in [../roadmap.md](../roadmap.md).

The stages are named SA, SB and SC ("S" for sources), and their steps SA1, SB1, SC1 and so on, so that they do not clash with the plan A, B, C of [semantics.md](semantics.md), the panel's steps P1–P10 or the chrome's C0–C9.

Counts and line numbers are at a54d9435 (the release of 0.9.0). They come from three read-only audits of that commit (2026-10-31), checked where this page says so, and from searches of the code.

## 1. The diagnosis

In every layer, a fact has a source: the word model, the argument interpreter, `resolveName`, the message catalog, the note levels. But nothing forces callers to use it. New code reads the tree or the text again, or keeps its own table, and each fix of the source leaves the copies behind.

The refactoring of October 2026 ([refactor.md](refactor.md)) removed 55 such copies. It fixed instances, not the mechanism: no test stopped the next copy. The few facts that have a guard test stayed clean: the names guard of src/explain/, the syntax boundary, the web page's storage, the trust allow-list.

So each fact gets a source and a guard: a test that fails on a new reading outside the source. Today's offenders go into a known list that may only shrink, as [word-source.md](word-source.md), section 4, does for words.

## 2. Design before wording

Decided by the maintainer on 2026-10-31: "If keeping today's explanations has bent the overall design, fix the design even if the explanations change: a clean, consistent design should produce clean explanations."

- **The model is the source.** An explanation says what the model knows. Where a clean model cannot support a text, the text changes: it gets simpler, or less precise. The model does not grow a special case to keep it.
- **Refactoring steps need not keep explanations byte-identical.** Each PR lists the explanation changes it makes (in its description, with a few before/after lines of test/snapshot.ts or a dump). None may contradict bash or the tool: the probes, the example tables and the renderings check (test/support/renderings.ts) still pass. A change users notice gets a CHANGELOG line.
- **Less precise is not wrong.** "`b` is a source or the destination, depending on how many words `$a` gives" is true. "`b` is the destination" is wrong when `$a` gives none. The first is allowed; the second is a bug.

## 4. Stages

### Stage SA: the guards (now, beside the UX work)

One test per fact, each with a known list of today's offenders that may only shrink (an entry that matches less than its count is stale, and fails). Tests and fixtures only; no src/ change, no CHANGELOG. Each guard is a small PR; SA2 to SA5 may go together.

1. **SA1. Words** (row 1): test/word-source.test.ts and test/fixtures/word-source-known.json, as [word-source.md](word-source.md), section 4, details: it is the detailed plan of row 1, and its step 1. Done in #528.
2. **SA2. Command reading** (row 2): `interpret(` calls, and option scans by regex (`/^-…/`, tests of an option's `.text`), outside src/argv/ and the future `commandRead`. Done: test/command-reading.test.ts and test/fixtures/command-reading-known.json (each decider names `commandRead` as its destination), on the shared scanner test/support/scan.ts. Row 3, the loops over `command` and `builtin`, is not found by its rule and waits for SC2.
3. **SA3. Command names in src/examples** (row 5): the names guard of test/explain-imports.test.ts also scans src/examples/, except the language interpreters (jq, awk, sed, perlrun, yaml, regex). Done: the guard's known list moved to test/fixtures/names-known.json (text, count, kind, reason). A switch that dispatches to a command's simulator counts (kind `registry`), as M6 says the name switches can go; the guard stops new ones. The guard also finds `cmd.endsWith('grep')`, and a table of functions keyed by command name (`FILTERS = { cat: runCat, … }`) with its lookups by a stage's command (`FILTERS[stage.cmd]`).
4. **SA4. Note levels** (row 13): severity numbers, level words, the glyphs `⚠` and `ⓘ`, and codicon names of levels, outside the level table. Its list empties in three-levels step 1. Done: test/note-levels.test.ts and test/fixtures/note-levels-known.json. The table is src/levels.ts since three-levels step 1a (the catalog, src/messages.ts, keeps each note's level); the guard reads src/, cli/, web/ and media/ (.ts, .js, .css), and `error` counts only where it is a level's (`i.severity === 'error'`), not the syntax tree's `error` node type.
5. **SA5. Catalog facts** (row 14): `cx.note` and `cx.say` with a plain string instead of a catalog fact. Its list empties before P7a. Done: test/note-strings.test.ts and test/fixtures/note-strings-known.json. It builds one TypeScript program over src/explain/ and src/examples/ (about 1.5 s, the type of the argument tells a fact from a string), and reads the rest of src/ syntactically.

Order: SA1 first (done, #528), then SA2 to SA5 (all done: #532, #533, #535, #537). Stage SA is complete; the migrations are stage SC (after 0.10.0). Size: small each.

## 5. The rule from now on

- **A new fact gets a source and a guard in the same PR.** The PR adds its row to the table of section 3. A fact with a source but no guard is not done.
- **A copy found later goes into its guard's known list**, with the step that removes it, or is fixed in the same PR.
- **A design review checks the table**: for each fact the change touches, that it reads the source, and that the guard still passes without new known entries.
- **Design before wording** (section 2): a text that needs a special case of the model is changed instead.
