# Unreleased changes, in detail

The short list is in [CHANGELOG.md](../../CHANGELOG.md#unreleased).

## New

### Python regular expressions

The patterns of Python's `re` module are explained in `.py` files (#748, docs/design/python-regex.md), with the reference Python 3.15.

- **Which calls.** `re.compile`, `search`, `match`, `prefixmatch`, `fullmatch`, `findall`, `finditer`, `split`, `sub` and `subn`, by the names the file imports (`import re as regex`, `from re import sub`), when the first argument is string literals: `r'^\d+$'`, `"\\d+"`, `r'\d+' r'\.'` joined, a triple-quoted one over several lines (the call is explained whole on each of its lines), a bytes pattern `rb'\d+'`. An f-string with a field and a pattern built at run time are not read yet.
- **Flags.** The flags argument is read, in its slot or as `flags=`: `0`, `re.NOFLAG`, and names joined by `|`, short or long (`re.I | re.MULTILINE`), by the names the file imports (`from re import I`). Each name gets a row with what it does. Then `^` and `$` say "the start and end of each line" with `re.M`, letters "in either case" with `re.I`, `.` takes a newline with `re.S`, and `\w`, `\d`, `\s`, `\b` are ASCII with `re.A` or in a bytes pattern (by the locale with `re.L`). Flags that are not a literal (`flags=opts`) are said to be not known, and each part whose meaning depends on them says so; a name beside them is still on (`re.X | extra` is VERBOSE). Where VERBOSE is not known, a pattern that only VERBOSE makes valid (`(?i) a  # see [1`) is no Error: its row says Python refuses it without `re.VERBOSE`.
- **Inline flags.** `(?i)` at the start sets the flags for the whole pattern, `(?i:…)` and `(?-i:…)` inside a group. `a(?i)b` is an Error: "global flags not at the start of the expression", an error since Python 3.11. So are the inline flags Python refuses: `(?L)` in a str pattern, `(?u)` in a bytes one, `(?au)`, `(?-a:…)`, `(?i-i:…)`.
- **VERBOSE.** With `re.X` or `(?x)`, whitespace is ignored and `#` starts a comment, except in a set or after a backslash: each comment is a row, and a space between two items is a row "ignored". `a* ?` is an Error ("multiple repeat"), and `a{1, 3}` is the text `a{1,3}`, no count. A message of a pattern over several lines gives the line and column, as Python's does.
- **Bytes patterns.** `\u`, `\U` and `\N{…}` are Errors in a bytes pattern ("bad escape \u").
- **A flag in the slot of `count`.** `re.sub(p, r, s, re.I)` is a Warning at `re.I`: it is passed as `count` (2), so at most two matches are replaced and the pattern stays case-sensitive. The same for `subn`, for `split`'s `maxsplit`, for `count=re.I` by keyword, and whatever the pattern is (`re.sub(pat, '', s, re.I)`). The Warning adds that Python 3.13 and later warn when `count` or `maxsplit` is passed by position.
- **What is said.** Each part of the pattern, at its place in the file: `\d`, `(?P<frac>…)` ("Named group `frac` (group 1)"), `[a-z]`, the quantifiers. Python's meanings where they differ from PCRE: `.` is any character but a newline, `\w`, `\d`, `\s` and `\b` take letters, digits and spaces of any script (`\w+` matches `日本語`), `\Z` is the end of the text only, `$` also stands before a final newline, `\v` is a vertical tab, `(?i)` sets the flags for the whole pattern, and `[[:alpha:]]` is a set of its characters followed by `]`. `match` says the pattern is matched at the start, `fullmatch` against the whole string, `prefixmatch` that it needs Python 3.15.
- **Errors.** A pattern Python refuses is an Error in Problems, `--check` and the panel, with Python's own message: `\e`, `\h`, `\G`, `\x{41}` ("bad escape \e at position 0"), `\x4` ("incomplete escape"), `\2` with one group ("invalid group reference 2"), `(a\1)` ("cannot refer to an open group"), `\777`, an unclosed `[` or `(`, a final `\`, a glob taken for a regex (`*.txt`: "nothing to repeat at position 0"), `a**` ("multiple repeat"), `x{2,1}` ("min repeat greater than max repeat") and a `)` that closes no group ("unbalanced parenthesis").
- **Which files.** A `.py` file that imports `re` gets the status bar item, the panel's button and the problems even with no `subprocess` or `os` call.
- **The chip and the panel.** On a pattern's line, the shell chip says "no shell (Python regex)", and the panel's top row is "Python regex (argument of `re.search`)". In a file with no shell code, the chip on a line outside every pattern says "no shell"; before, it said "auto" ("set by each part"). On a line with shell code too (`re.match(p, x); os.system('ls')`), the shell code is explained. Read word by word, the pattern's root is "Python regex", read by the function it is passed to; "Copy as Markdown" fences the line as `python`.
- **`grep -P` and the other shell tools** read as before, but a quantifier after a comment now repeats the item before it: `grep -P 'a(?#c)*'` says "repeat `a`" (before, "repeat `(?#c)`").

## Fixed

### Python strings and imports

The Python host now reads a `.py` file with one lexer, one table of Python's escapes and one table of its imports (#759).

- **Escapes in a list of arguments.** A word's value has every escape undone: `subprocess.run(["printf", "\a"])` passes a BEL character (before, the text `\a`), and `"a\012b"` a newline (before, a NUL and `12`). In bytes, `b"\u0041"` keeps its backslash, as Python does.
- **Escapes in a command string.** `os.system("printf a\012b")` and `"echo a\x0ab"` end a command at the newline, as `\n` does (`printf a;b`); before, `\012` stayed as written, and `\x0a` broke the line in two. `"\101"` is `A`; `\r`, `\0`, `\b` and the other one-letter escapes give their characters.
- **`\N{…}`.** Without a table of Unicode names, the character of `"\N{BULLET}"` is not known: in a command string it is one character, quoted (`echo "${py_N_BULLET}"`, whose text names it), and in a list of arguments the word is an expression whose value is not shown. Before, it was read as the text `\N{BULLET}`.
- **Newlines and the shell's quotes.** An escaped newline is read as sh reads it there: inside the shell's quotes it is a newline of the word (`subprocess.run("echo 'x\ny'", shell=True, executable="/bin/bash")` is `echo 'x'$'\n''y'`; with `/bin/sh`, which has no `$'…'`, a placeholder of the one character, `printf 'hello'"${py_newline}"''`, whose text says it is a newline), and after a backslash it is a line continuation (`"echo a \\\nb"` runs `echo a b`). Before, each was a `;`.
- **Parentheses and lists.** A string in parentheses is the string: `os.system(("echo hi; ls"))` is the shell's, and `subprocess.run(("echo a " "b"), shell=True)` no longer says the shell runs the first item of a list. A tuple (`("ls", "-l")`) is still a list. Literals joined in a list (`["a" "b"]`), an f-string with no field and a word in parentheses are words, no longer Python expressions.
- **Two calls on a line.** Of `os.system("cd x"); os.system("make all")`, the first is explained, and the second is left out; before, both read `cd xmake all`.
- **f-strings.** A self-documenting field shows its text: `f"echo {x=}"` is `echo x=${py_x}`, as Python writes `x=` before the value. A field's expression is read to its end: `{a != b}` names `a != b` (before, `a`).
- **Literals across a comment.** `os.system("echo a"  # why` with `"b")` on the next line joins the two literals, as Python does; before, the second was left out.
- **Imports and calls.** `import os.path` binds `os`, and an import after `;` counts (`import sys; import os`); `os . system(…)` is a call too. Text inside a string or a docstring is never a call, even at the start of a line.
- **`executable=`.** A bytes literal names the shell (`executable=b"/bin/bash"`); a variable no longer does by its name (`executable=bash` is read as `/bin/sh`).
