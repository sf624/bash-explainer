# Unreleased changes, in detail

The short list is in [CHANGELOG.md](../../CHANGELOG.md#unreleased).

## New

### Python regular expressions

The patterns of Python's `re` module are explained in `.py` files (#748, docs/design/python-regex.md), with the reference Python 3.15.

- **Which calls.** `re.compile`, `search`, `match`, `prefixmatch`, `fullmatch`, `findall`, `finditer`, `split`, `sub` and `subn`, by the names the file imports (`import re as regex`, `from re import sub`), when the first argument is string literals: `r'^\d+$'`, `"\\d+"`, `r'\d+' r'\.'` joined, a triple-quoted one over several lines (the call is explained whole on each of its lines), a bytes pattern `rb'\d+'`. A pattern built at run time is not read; a method of a compiled pattern is read with the pattern of its `re.compile` (below).
- **Flags.** The flags argument is read, in its slot or as `flags=`: `0`, `re.NOFLAG`, and names joined by `|`, short or long (`re.I | re.MULTILINE`), by the names the file imports (`from re import I`). Each name gets a row with what it does. Then `^` and `$` say "the start and end of each line" with `re.M`, letters "in either case" with `re.I`, `.` takes a newline with `re.S`, and `\w`, `\d`, `\s`, `\b` are ASCII with `re.A` or in a bytes pattern (by the locale with `re.L`). Flags that are not a literal (`flags=opts`) are said to be not known, and each part whose meaning depends on them says so; a name beside them is still on (`re.X | extra` is VERBOSE). Where VERBOSE is not known, a pattern that only VERBOSE makes valid (`(?i) a  # see [1`) is no Error: its row says Python refuses it without `re.VERBOSE`.
- **Inline flags.** `(?i)` at the start sets the flags for the whole pattern, `(?i:…)` and `(?-i:…)` inside a group. `a(?i)b` is an Error: "global flags not at the start of the expression", an error since Python 3.11. So are the inline flags Python refuses: `(?L)` in a str pattern, `(?u)` in a bytes one, `(?au)`, `(?-a:…)`, `(?i-i:…)`.
- **VERBOSE.** With `re.X` or `(?x)`, whitespace is ignored and `#` starts a comment, except in a set or after a backslash: each comment is a row, and a space between two items is a row "ignored". `a* ?` is an Error ("multiple repeat"), and `a{1, 3}` is the text `a{1,3}`, no count. A message of a pattern over several lines gives the line and column, as Python's does.
- **Bytes patterns.** `\u`, `\U` and `\N{…}` are Errors in a bytes pattern ("bad escape \u").
- **A flag in the slot of `count`.** `re.sub(p, r, s, re.I)` is a Warning at `re.I`: it is passed as `count` (2), so at most two matches are replaced and the pattern stays case-sensitive. The same for `subn`, for `split`'s `maxsplit`, for `count=re.I` by keyword, and whatever the pattern is (`re.sub(pat, '', s, re.I)`). The Warning adds that Python 3.13 and later warn when `count` or `maxsplit` is passed by position.
- **f-strings.** A field of an f-string pattern is read as a hole (#750): in `re.search(rf"^{prefix}\d+$", s)`, the row of `{prefix}` says that its value is read as a regex, whose `.`, `*` and `[` have their special meaning, and that what stands around it is read as if the value had no group or `|` of its own. `{{2}}` is the quantifier `{2}`. A field `{re.escape(x)}` is plain text, in the pattern and in a set. With `re.VERBOSE` (or flags not known), the row of a field also says that whitespace in its value is ignored and a `#` in it comments out the rest of its line. Where a field decides how the pattern reads (`a{{{n}}}`, `[{a}-z]`, `\x{h}`), the pattern is not read, and its row says which field decides. Before, an f-string with a field was not explained.
- **Strings that are not raw.** `re.search("\bword\b", s)` is a Warning at the first `\b`: without `r`, the string makes it a backspace (U+0008), so the pattern matches a backspace there, not a word boundary. `"(a)\1"` is a Warning too: `\1` (or `\12`) is the character U+0001, not a reference to group 1. Neither is said in a set (`[\b]`, `[\1]`), where a regex reads the same character, nor for `\0`, `\012` or `\101`, which a regex reads as octal too. A backslash the string keeps (`"\d+"`) is no problem, since Python warns of it itself (SyntaxWarning, since 3.12): the pattern's row says that the string keeps `\d`, and that `r"…"` keeps it with no warning.
- **What is said.** Each part of the pattern, at its place in the file: `\d`, `(?P<frac>…)` ("Named group `frac` (group 1)"), `[a-z]`, the quantifiers. Python's meanings where they differ from PCRE: `.` is any character but a newline, `\w`, `\d`, `\s` and `\b` take letters, digits and spaces of any script (`\w+` matches `日本語`), `\Z` is the end of the text only, `$` also stands before a final newline, `\v` is a vertical tab, `(?i)` sets the flags for the whole pattern, and `[[:alpha:]]` is a set of its characters followed by `]`. `match` says the pattern is matched at the start, `fullmatch` against the whole string, `prefixmatch` that it needs Python 3.15.
- **Examples** (#751). Under the pattern, as for `grep` and `[[ =~ ]]`, and turned off with the kind `regex` of `examples.disabled`. `search`, `match`, `prefixmatch`, `fullmatch` and `compile` show strings that match and strings that do not, with the function's anchors: `re.fullmatch(r'\d{3}-\d{4}', s)` matches `123-1234` but not `123-123`; a compiled pattern is matched as its `search` does. Where the subject is a literal, the example shows it and what the call gives back, as Python prints it: `re.search(r'\d+', 'abc 123')` gives `<re.Match object; span=(4, 7), match='123'>`, `re.sub(r'\s+', ' ', 'a  b\tc')` gives `'a b c'`, `re.findall(r'(\w+)=(\d+)', 'a=1, b=22')` gives `[('a', '1'), ('b', '22')]` (strings with no group or one, tuples with two or more), `re.split(r'(,)|(;)', 'a,b;c')` gives `['a', ',', None, 'b', None, ';', 'c']`, and `re.subn` the text and the count. Where the subject is not a literal, a made-up string is the input, labelled so. A `count` or `maxsplit` written as a number is followed, and so is a flag in its slot (`re.sub(r'a', 'b', 'aAa', re.I)` replaces two). Empty matches are found as Python finds them (`re.sub('x*', '-', 'abxd')` gives `'-a-b--d-'`), `$` matches before a final newline, `\Z` does not, and `.` takes no newline without `re.S`. There is no example for an atomic group, a possessive quantifier, a conditional, `\N{…}`, a backreference to a group that may not take part, a repeat whose next iteration may match nothing (`re.split(r'(\s*)?,', 'a, b')`: Python takes such an iteration, JavaScript does not), a group repeated in a repetition in which it may not run (`re.findall(r'(?:x(a)*)+', 'xaxx')`), `re.L`, flags that are not known, a `(?i:…)` of a group, case folding past ASCII, a replacement that is not a literal (a function) or whose template has a field of an f-string or an error, `finditer`, or a subject or replacement past ASCII or with a `\r` or a control character: no wrong one. A result too large to make (`re.sub(r'a', 'R' * 10000, 'a' * 10000)` written out) is "not computed". The box of test strings in the panel runs ASCII text only: `re.search(r'\d+', s)` on `tel １２３` says it is not computed, as Python's `\d` matches `１`; and there is no box where JavaScript would give a group's text otherwise than Python (`(?:(a)|b)+`).
- **Errors.** A pattern Python refuses is an Error in Problems, `--check` and the panel, with Python's own message: `\e`, `\h`, `\G`, `\x{41}` ("bad escape \e at position 0"), `\x4` ("incomplete escape"), `\2` with one group ("invalid group reference 2"), `(a\1)` ("cannot refer to an open group"), `\777`, an unclosed `[` or `(`, a final `\`, a glob taken for a regex (`*.txt`: "nothing to repeat at position 0"), `a**` ("multiple repeat"), `x{2,1}` ("min repeat greater than max repeat"), a `)` that closes no group ("unbalanced parenthesis"), a lookbehind whose contents may match more characters or fewer (`(?<=^|\s)\w+`, `(?<=a+)`: "look-behind requires fixed-width pattern", with what its contents may match), and a reference in a lookbehind to a group opened in it (`(?<=(a)\1)`).
- **Replacement templates** (#752). The replacement of `re.sub` and `re.subn` gets a row when Python reads it as a template (it has a backslash, or a field of an f-string), with a row for each part: `re.sub(r'(\w+)@(\w+)', r'\2 at \1', s)` says that `\2` is what group 2 matched, ` at ` text put in as it is, and `\1` what group 1 matched; `\g<name>` names the group and its number, `\g<0>` is the whole match, `\n`, `\\` and `\101` are characters, and `\-` is put in with its backslash. A group the pattern lacks is an Error, with Python's message ("invalid group reference 3 at position 12"; "unknown group name 'x'", an `IndexError`), and so are an unknown letter (`\d`, `\x41`: "bad escape \d") and a final `\`. The example applies the template to each match, a group that did not take part putting in nothing: `re.sub(r'(\w+)@(\w+)', r'\2 at \1', 'me@host, you@there')` gives `'host at me, there at you'`. A string without `r` that makes `\1` the character U+0001 (`re.sub(p, '<\1>', s)`) is a Warning, as in a pattern. A plain replacement (`' '`) gets no row, as before. Before, a replacement with a backslash got no example.
- **Compiled patterns** (#752). `EMAIL = re.compile(r'…')`, then `EMAIL.findall(s)` or `EMAIL.sub(r'<\1>', s)` further down: the method's line says the method of which pattern it is and on which line it was compiled (its pattern's rows stay on that line), reads its own arguments (no pattern, no flags; `pos` and `endpos` get rows), and gets the example of the call with the pattern and the flags of the compile, `pos` and `endpos` followed when they are numbers: `WORD.match('ab cd', 3, 5)` gives `<re.Match object; span=(3, 5), match='cd'>`, as `match` starts at `pos`, where `^` does not match. A name is linked only where the file binds it once, by `NAME = re.compile(<literals>…)` at the top of the file or in a function: a name assigned twice, a parameter, a loop's target or a name a function binds again is not linked, and neither is a call where Python would not see the name (another function, a class's methods, before the statement at the top). Before, the methods of a compiled pattern were not explained.
- **Which files.** A `.py` file that imports `re` gets the status bar item, the panel's button and the problems even with no `subprocess` or `os` call.
- **The chip and the panel.** On a pattern's line, the shell chip says "no shell (Python regex)", and the panel's top row is "Python regex (argument of `re.search`)". In a file with no shell code, the chip on a line outside every pattern says "no shell"; before, it said "auto" ("set by each part"). On a line with shell code too (`re.match(p, x); os.system('ls')`), the shell code is explained. Read word by word, the pattern's root is "Python regex", read by the function it is passed to; "Copy as Markdown" fences the line as `python`.
- **`grep -P` and the other shell tools** read as before, but a quantifier after a comment now repeats the item before it: `grep -P 'a(?#c)*'` says "repeat `a`" (before, "repeat `(?#c)`").

## Fixed

### Python strings and imports

The Python host now reads a `.py` file with one lexer, one table of Python's escapes and one table of its imports (#759).

- **Escapes in a list of arguments.** A word's value has every escape undone: `subprocess.run(["printf", "\a"])` passes a BEL character (before, the text `\a`), and `"a\012b"` a newline (before, a NUL and `12`). In bytes, `b"\u0041"` keeps its backslash, as Python does.
- **Escapes in a command string.** `os.system("printf a\012b")` and `"echo a\x0ab"` end a command at the newline, as `\n` does (`printf a;b`); before, `\012` stayed as written, and `\x0a` broke the line in two. `"\101"` is `A`; `\r`, `\0`, `\b` and the other one-letter escapes give their characters.
- **`\N{…}`.** Without a table of Unicode names, the character of `"\N{BULLET}"` is not known: in a command string it is one character, quoted (`echo "${py_N_BULLET}"`, whose text names it), and in a list of arguments the word is an expression whose value is not shown. Before, it was read as the text `\N{BULLET}`.
- **Newlines and the shell's quotes.** An escaped newline is read as sh reads it there: inside the shell's quotes it is a newline of the word (`subprocess.run("echo 'x\ny'", shell=True, executable="/bin/bash")` is `echo 'x'$'\n''y'`; with `/bin/sh`, which has no `$'…'`, a placeholder of the one character, `printf 'hello'"${py_newline}"''`, whose text says it is a newline), and after a backslash it is a line continuation (`"echo a \\\nb"` runs `echo a b`). Before, each was a `;`.
- **Parentheses and lists.** A string in parentheses is the string: `os.system(("echo hi; ls"))` is the shell's, and `subprocess.run(("echo a " "b"), shell=True)` no longer says the shell runs the first item of a list. A tuple (`("ls", "-l")`) is still a list. Literals joined in a list (`["a" "b"]`), an f-string with no field and a word in parentheses are words, no longer Python expressions.
- **Two calls on a line.** Of `os.system("cd x"); os.system("make all")`, the first is explained, and the second is left out; before, both read `cd xmake all`.
- **f-strings.** A self-documenting field shows its text: `f"echo {x=}"` is `echo x=${py_x}`, as Python writes `x=` before the value. A field's expression is read to its end: `{a != b}` names `a != b` (before, `a`).
- **Literals across a comment.** `os.system("echo a"  # why` with `"b")` on the next line joins the two literals, as Python does; before, the second was left out.
- **Imports and calls.** `import os.path` binds `os`, and an import after `;` counts (`import sys; import os`); `os . system(…)` is a call too. Text inside a string or a docstring is never a call, even at the start of a line.
- **`executable=`.** A bytes literal names the shell (`executable=b"/bin/bash"`); a variable no longer does by its name (`executable=bash` is read as `/bin/sh`).
